# 挨饿荒野 · 物资地图

游戏《挨饿荒野》各地图物资摆放位置的可视化网页：缩放/拖拽查看地图，按物资筛选并显示摆放圆点，支持搜索、最多 5 种物资同时叠加显示。

顶栏两个 Tab：

| Tab | 内容 |
|---|---|
| **物资位置** | 各图物资摆放点（圆点），支持搜索、自定义颜色/大小、最多 5 种叠加 |
| **猎物区域** | 各图**猎物活动区矩形框**（哪些坐标范围内能刷出/抓到该猎物），可多选高亮 |

## 物资映射.csv

每行一个物资编号：

```
编号,名称,英文名,预制体,图标
13,竹子,ZhuziTree,Prefab/Tree/ZuziTree,zhuziCailiao.png
```

- 映射是全局的：同一编号在所有地图中共用一条映射；各地图的数量由摆放记录自动统计。
- `图标` 只写文件名，页面按 `wupingIcon/<图标>` 加载；`wupingIcon` 里没有时回退 `../assets/Texture2D/`，两级都失败（或该行本来没图标）时**显示首字徽标**——取名称首字放进彩色圆角方块，与「猎物区域」列表同一套 `.zph` 样式。
- 改完 CSV 刷新页面即可生效（无需改 HTML）。
- **`名称` 的写法**：`物品名[变体]`，如 `藤条`、`藤条[树上]`、`藤条[雪地+树上]`、`鸟蛋[地面巢]`。变体取自预制体路径（见 `文档/逆向_物资分布字段说明.md`），同一物品的不同模型因此能并排辨认，又不至于混成一个。
- **`名称` 留空的行**：页面按 `名称 → 英文名 → #编号` 三级回退，都能认出来（图标位置显示首字徽标）。
- 名称不要指望手工维护：跑 `python pythonTool/修订物资映射.py` 会按「官方物品表 → 预制体 → 旧名」的优先级统一填写，`--dry` 可先看会改哪 70 多条。
- 需要批量补齐新版本条目时跑 `python pythonTool/补充新物资条目.py`（见下），它会自动把「存档里出现过但 CSV 没有」的编号，以及新版本新增的枚举（≥460）追加进来。

## 按物品聚合（工具栏开关）

顶栏的「按物品聚合」勾选框控制左侧列表的粒度，选择存在浏览器本地（`localStorage.aehyAgg`）：

- **关**（默认）：一个世界物件一条，如 `藤条`、`藤条[树上]`、`藤条[雪地]`、`藤条[雪地+树上]` 各占一行。
- **开**：同一物品的多个模型合并成一行 `藤条 ×588（4变体）`，点一次同时高亮全部变体点位；悬停条目可看它由哪几个物件组成。

分组依据是 `data/物件变体.csv` 的 `物品id` 列（来自游戏的 `PlaceConstants.couldFindWuping`）；没有物品映射的物件（宝箱、木雕、动物巢等）各自成组。所以聚合只对"同一物品多种模型"生效——例如图 8 挪威雪山 44 个物件合成 42 组、图 15 纳米比亚 45 → 41 组，图 1 泰国丛林没有变体，28 个物件仍是 28 组。

> `data/物件变体.csv` 加载失败（例如 `file://` 直接双击打开）时自动退化为按编号显示，页面不会报错。

## 物资名称.csv（游戏名称表全量导出）

`data/物资名称.csv` 与 `aehy-mod-master/tools/place_out/wuping_names.json` 是同一份数据的两种形态，由 `pythonTool/导出物资名称.py` 从 `libil2cpp.so` 生成，不靠人工维护。

数据源是 `BuildUtil$$.cctor` 里对 `cailiaoSpriteMap`（`Dictionary<Wuping, string[]>`）的 490 次 `Add`：每个条目现造一个 `string[]` 再逐项填字面量。（同一个 cctor 里这类字典共 5 个、合计 613 次 `Add`，脚本按"条目最多的一组 + 首元素是图标路径"识别目标字典。）数组**固定 7 槽**（489/490 条为 7，`16 大块烤肉` 为 5）：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 含义 | 图标路径 | 简体名 | 繁体名 | 英文名 | 描述简体 | 描述繁体 | 描述英文 |

缺失项是**空串而不是裁掉**——这点很重要：早期手动整理的表把"繁体与简体相同"的项去掉，导致后续下标整体前移，英文名会落到 `[2]` 上。现在的 `wuping_names.json` 一律保留 7 槽，`make_csv.py`（取 `[1]` 中文、`[3]` 英文）等下游因此才拿得到正确的英文名。

现状：490 条 / key 0..493，枚举 494 个成员里缺 4 个（`144`/`145` `GaoshanFloorStone1/2`、`241` `None` 占位、`415` `Barrior`（游戏内就是这么拼的）），游戏本身没给它们配名称数组。

## 编号是哪一套 id？（重要）

`物资位置.json` / `物资映射.csv` 里的编号是**世界物件 id**（存档 `wpType`、`Prefab/...` 预制体），**不是** `Wuping` 枚举：

| 编号 | 世界物件（本页用的） | `Wuping` 枚举（`物资名称.csv` 用的） |
|---|---|---|
| 202 | 石头 `Prefab/Build/ThrowStone` | 草鞋 `Shoe` |
| 13 | 竹子 `Prefab/Tree/ZuziTree` | 肉条 `Wuping13` |

同一件东西在世界上有多个模型（地面/树上/雪地/水面），各是不同物件 id，采到的物品相同——例如藤条 = `54 普通 / 155 树上 / 116 雪地 / 117 雪地+树上`。这层关系由 `data/物件变体.csv` 给出（`物品id / 物品名 / 变体` 三列），规则与证据见 `文档/逆向_物资分布字段说明.md`。变体后缀由预制体路径推断（`Snow`/`Up`/`Floor`/`Animals/*Home` 等），预制体本身来自 `data/预制体映射.json`。

## 物资位置数据源（data/物资位置.json）

页面打开时会 `fetch("data/物资位置.json")`，成功则用它**覆盖** HTML 里内联的旧数据：每张图的 `rows`（物资点）、`prm`（世界矩形）、`tw/th`（底图尺寸）、`bg`（底图路径），并补齐存档里才有的新地图。加载失败（`file://` 直接双击、或文件缺失）就继续用内联数据，顶栏会提示「数据:内置」。

```json
{
  "meta": { "rowFields": ["id", "x", "z", "s", "tag"], "placeFields": "level/name/prm/tw/th/bg/prmSource/count/rows" },
  "places": [
    { "level": 1, "name": "泰国丛林", "prm": [500,194,-188.7,82.5,52.2,-88.6],
      "tw": 692, "th": 269, "bg": "地图图片/图1_泰国丛林.png",
      "prmSource": "official", "count": 990,
      "rows": [[1099, 12.85, -2.86, 0, "tag_0"]] }
  ]
}
```

- `rows` 的每项按 `[id, x, z, s, tag]` 排列：`id` 物资编号（同 `物资映射.csv` 的 `编号`）、`x/z` 世界坐标、`s` 状态（0 未拾取 / 1 已拾取）、`tag` 存档内唯一标记。
- `prm` 是 `[w, h, l, r, t, b]`：`l/r` = 世界 x 范围、`b/t` = 世界 z 范围（`w/h` 在换算中会被约掉，只有 `l/r/t/b` 影响位置）。网页换算式：`px = (x-l)/(r-l)*tw`，`py = (t-z)/(t-b)*th`。
- `prmSource` **现在 15 张图全是 `official`**：矩形取自游戏自己的常量表 `Constants.sceneDituWHMap`（`float[6]`），与 `DituManager.V3ToV2` 用的是同一份数据，详见下一节。早先图 10/12/15 用包围盒反推（`estimated`）的版本已被替换。
- `bg` 为空串表示没有底图，页面会画一张网格当坐标系（15 张图现在都有底图，这条只是以后新增地图时的兜底）。
- 存档里的 level 与网页「图 N」一一对应。

**更新流程**：把新存档放到 `data/marooned_with_ed.db`（或改脚本里的路径），然后

```bash
python pythonTool/导出物资位置.py
```

脚本把三张表 `marooned_wuping_data`（level 1–9）、`_data2`（10–13）、`_data3`（14、15）按 level 取出，写成上面的 JSON。改完刷新页面即可，无需重跑任何改 HTML 的脚本。地图名称/`prm`/底图尺寸等元信息在脚本顶部的 `PLACES` 表里维护，新增地图在里面加一行。

## 坐标映射（世界坐标 → 底图像素）

网页用的就是游戏自己的公式，没有任何人工校准量：

```js
px = (x - left) / (right - left) * tw;      // tw = 底图像素宽
py = (top  - z)  / (top   - bottom) * th;   // th = 底图像素高
```

- **出处**：`DituManager.V3ToV2(Vector3)`（本版 RVA `0xD27B54`）。反汇编就是
  `w·(x−(l+r)/2)/(r−l)` 与 `h·(z−(t+b)/2)/(t−b)`，再各自 `+ w/2`、`+ h/2` 平移到左上角原点 —— 化简后即上面的式子。
- **矩形来自** `Constants.sceneDituWHMap : Dictionary<int, float[]>`，每个值是 `[w, h, left, right, top, bottom]`。`w/h` 只是底图的基准像素，在公式里和 `tw/th` 一起约掉。
- **拿法**：cctor 用 `RuntimeHelpers.InitializeArray` 从静态字段数据填这个字典，字段句柄静态不可解；但数组本体就是**连续的 6 个 float**，直接扫 `global-metadata.dat` 即可，再用存档点位做交叉验证（矩形必须包住该图全部点位、矩形/点位比例与其它图同量级、PNG 宽高比与 `w/h` 一致）。工具：`python pythonTool/导出地图矩形.py`，产物 `data/地图矩形.json`。

## 图例自定义颜色 / 大小

选中物资后，左下角图例每一行自带两个控件：

- **圆形色块**：点击弹出取色器，修改该物资在地图上的圆点颜色（同时同步左侧列表圆点与图例）；
- **数字框**：修改圆点大小（3–20 px，默认 5）；
- 设置了自定义样式后，图例底部出现 **↺ 恢复默认样式**。

自定义按物资编号保存在浏览器 `localStorage`（键 `aehyCustom`），刷新和下次打开都保留；仅对当前浏览器有效，换设备/清缓存后回到默认配色。不修改任何数据文件。

## 猎物区域 Tab

数据来自游戏程序集里的 `BasePlace.ListAnimalZone()`，字段与语义：

```json
{
  "animals": { "44": { "en": "TuziObj", "zh": "兔子", "icon": "tuziObj.png", "nameSrc": "official" } },
  "places": [
    { "place": 1, "name": "Place1",
      "bounds": { "minX": -200, "minZ": -70, "maxX": 90, "maxZ": 70 },
      "animals": [ { "key": 44, "boxes": [ { "minX": -168, "minZ": 25, "maxX": -40, "maxZ": 70 } ] } ] }
  ]
}
```

- 一个猎物可以有多块互不相连的栖息地，`boxes` 里每一块都是一个矩形；
- 判定是**开区间**：`minX < x < maxX && minZ < z < maxZ`（只看平面坐标，忽略高度）；
- `place` 编号与网页「图 N」一一对应（Place1 = 图1 泰国丛林，以此类推），目前覆盖 Place1–Place15（图 15 纳米比亚）。
- 图 10 荒野一家、图 12 幽冥之地、图 15 纳米比亚三张背景图都已到位，框直接画在底图上；这三张图的 `prm` 是估算值（见上一节），如与底图有偏移请按实际范围校准 `data/物资位置.json`。
- `nameSrc`：`official` 表示中文名取自 `物资映射.csv` 的 `Prefab/Animals/*Home` 记录，`inferred` 表示按英文枚举名推断；

交互与「物资位置」页一致：缩放/拖拽/悬停看坐标；左侧点猎物可高亮其活动区（可多选，选中后其余变暗）；`全选` 显示全部。

`物资地图.html` 里的 `ZDATA` 常量就是 `猎物区域.json` 的内嵌副本 —— **改数据后必须重跑 `pythonTool/新增HTML_猎物区域页.py`**，否则页面不会更新。

数据的推导过程、验证方法与可复用脚本见 `文档/逆向_陷阱与猎物区域/`（换游戏版本时按那里的手册重跑一遍即可）。

| `修改HTML_自定义颜色大小.py` | 图例自定义颜色/大小 |
| `新增HTML_猎物区域页.py` | 注入「猎物区域」Tab（样式 + DOM + JS 模块，数据取自 `data/猎物区域.json`） |
| `导出地图矩形.py` | **从 `global-metadata.dat` 扫出每图的底图世界矩形**（`Constants.sceneDituWHMap` 的 `float[6]`），用存档点位 + 底图宽高比做交叉验证后代价矩阵求最优配对，产出 `data/地图矩形.json`；`--apply` 可回写 `导出物资位置.py` 的 `PLACES` |
| `导出物资位置.py` | 从 `data/marooned_with_ed.db` 导出 `data/物资位置.json`；`prm` 优先取 `data/地图矩形.json`（官方表），地图名称/底图尺寸在脚本顶部 `PLACES` 表维护 |
| `新增HTML_物资数据外置.py` | 让网页启动时加载 `data/物资位置.json`（失败回退内置数据），并把 `CSV_URL` 指到 `data/` |
| `修订物资映射.py` | 按 `物件变体.csv` 的官方映射统一修订 `物资映射.csv` 名称（`物品名[变体]`）、校正 `预制体` 列、补齐空名；`--dry` 只看改动；先备份 `物资映射.bak.csv` |
| `补充新物资条目.py` | 把「存档里出现过但 CSV 没有」的编号 + 新版本新增枚举（≥460）追加进 `物资映射.csv`，只填编号与英文名，中文留空；`--dry` 只看不写 |
| `新增HTML_未命名物资显示英文名.py` | 列表标题按 `名称 → 英文名 → #编号` 三级回退，让中文还没填的条目仍能认出来 |
| `校验底图对齐.py` | 只读体检：按网页同一套公式把物资点映射成像素，统计「图外 / 落到边带 / 落到最亮空白区」三个指标，判断底图与 `prm` 是否对得上；可带地图号只查一张，如 `python pythonTool/校验底图对齐.py 15`；没装 pillow 时用内置 PNG 解码器，不报错 |
| `物资地图_原版备份.html` | 原始数据备份 |

脚本均可重复运行（已应用的修改自动跳过），并会同时更新 `物资地图.html` 与 `index.html`。

> `新增HTML_猎物区域页.py` 会把整个 `猎物区域.json` 内嵌进 HTML，且 `新增HTML_物资数据外置.py` 依赖它注入的模块，所以**两个改 HTML 的脚本按上面的顺序跑**：先 `新增HTML_猎物区域页.py`，再 `新增HTML_物资数据外置.py`。日常改物资点数据只跑 `导出物资位置.py` 即可，不需要碰 HTML。

## 日常更新流程

**更新物资点数据**（游戏里又逛了一圈/新版本存档）：

1. 把新存档放到 `data/marooned_with_ed.db`（文件名不同就改脚本默认值或用 `--db`）；
2. `python pythonTool/导出物资位置.py` 重新生成 `data/物资位置.json`；
3. 浏览器刷新验证（顶栏应显示「数据:外置JSON 19254点」，点数随存档变化）；
4. `git add -A && git commit -m "说明" && git push`。

**更新物资图标/名称**：

1. 修改 `data/物资映射.csv`（新增/改名图标、更名物资等）；
2. `python pythonTool/同步图标.py` 补齐图标；
3. 浏览器刷新验证；
4. 提交。

**新版本新增物资/猎物**（游戏更新后，存档里出现了不认识的编号）：

1. `python pythonTool/导出物资名称.py --version-dir <新版本目录> --csv data/物资名称.csv` 重新解出名称表（默认写 `place_out/wuping_names.json`，加 `--csv` 才刷新 `data/物资名称.csv`）；
2. `python pythonTool/补充新物资条目.py --dry` 先看一眼会补哪些（只读）；
3. 去掉 `--dry` 正式写入，`data/物资映射.csv` 会多出「只有编号 + 英文名」的行；
4. `python pythonTool/导出物资名称.py --fill-csv data/物资映射.csv` 按编号把这些空名称批量填上（只填空、可重复跑）；
5. `python pythonTool/同步图标.py` 补齐图标后提交。

**游戏版本更新（整套数据重跑，顺序不能乱）**：

```bash
# 0) Il2CppDumper 对新版 libil2cpp.so + global-metadata.dat 出 dump
#    （script.json / stringliteral.json / dump.cs → <版本目录>/Il2CppDumper-out/）

# 1) 物品名称表（Wuping → 图标/简中/繁中/英文/描述）
python pythonTool/导出物资名称.py --version-dir <版本目录> --csv data/物资名称.csv

# 2) 物件 id → 预制体（可 --compare 与当前表比对，交集应全一致）
python pythonTool/导出预制体映射.py --version-dir <版本目录> --compare data/预制体映射.json

# 3) 物品 → 物件 id 数组（在 mod 仓库里）
python ../aehy-mod-master/tools/export_couldfind.py --version-dir <版本目录>

# 4) 每关底图世界矩形（有新图/换底图必须重跑；--apply 回写 PLACES）
python pythonTool/导出地图矩形.py --meta <版本目录>/global-metadata.dat --apply

# 5) 物资点位（需要新存档 db）
python pythonTool/导出物资位置.py

# 6) 物件↔物品/变体对照表
python pythonTool/导出物件变体.py

# 7) 名称统一修订（先 --dry 预演）
python pythonTool/修订物资映射.py --dry && python pythonTool/修订物资映射.py

# 8) 体检：图外必须 0
python pythonTool/校验底图对齐.py
```

依赖关系：6 依赖 2/3，7 依赖 6，5 依赖 4。解不出来的新编号按 §「编号是哪一套 id」判断身份（查 `data/预制体映射.json` 的预制体名，再用中文字面量反查），原理、校验与踩坑清单见 `文档/逆向_版本更新手册.md`。

**更新猎物区域数据**（游戏版本更新后）：

1. 按 `文档/逆向_陷阱与猎物区域/README.md` 的「新版本复用手册」重跑工具链（注意 `il2cpp_array_new` 的地址每个版本都会变，`tt2.py` 已改成自动探测，识别不到时用 `AEHY_ARRNEW=0x...` 强制指定），得到新的 `data/猎物区域.json`；
2. `python pythonTool/新增HTML_猎物区域页.py` 把它注入网页；
3. `python pythonTool/新增HTML_物资数据外置.py` 重新接上物资位置数据源；
4. 刷新验证后提交。

## 数据来源

地图与摆放坐标来自游戏存档数据库 `data/marooned_with_ed.db`；物资编号/预制体/图标来自游戏资源（`assets/Sprite` 与 `assets/Texture2D`）；物资名称/描述（简繁英）由 `BuildUtil$$.cctor` 的 `cailiaoSpriteMap` 反汇编还原（`pythonTool/导出物资名称.py`）；物件 id → 预制体由 `PlaceConstants$$.cctor` 的 `prefabMap` 还原（`pythonTool/导出预制体映射.py`）；底图世界矩形由 `Constants.sceneDituWHMap` 还原（`pythonTool/导出地图矩形.py`）；猎物活动区由 `libil2cpp.so` 的 `BasePlace.ListAnimalZone()` 反汇编还原（方法见 `文档/逆向_陷阱与猎物区域/`）。仅供学习交流。
